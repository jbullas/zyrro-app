# Zyrro Named Identity System v1

## Core Objective

Generate a concise identity name that captures the user’s full Primary Signature Constellation.

The name must feel:

- accurate  
- sharp  
- resonant  
- memorable  
- identity-level

The user should feel:

**“That’s me.”**

Not:

- “That sounds clever.”  
- “That sounds random.”

Recognition first.
Brandability second.

---

# Core Principle

The Named Identity is not a summary.

It is a synthesis.

### Bad naming

Builder + Catalyst = Builder Catalyst

That is stacking.
Not synthesis.

### Good naming

The Awakening Architect

That compresses multiple signatures into one coherent identity.

---

# Naming Inputs

The system uses:

## Input 1 — Top 5 Primary Signatures

Mandatory.
Highest priority.

**Weight:** 70%

---

## Input 2 — Signature Rank Order

Important.
The top signature has higher naming authority.

**Weight:** 15%

---

## Input 3 — Dominant Tension Pattern

Important.
What creates friction shapes identity.

**Weight:** 10%

---

## Input 4 — Emerging Signature

Optional.
Used only if highly active in recent narrative.

**Weight:** 5%

---

# Naming Formula

Base formula:

**Modifier + Core Identity**

Examples:

- The Strategic Builder  
- The Awakening Architect  
- The Pattern Catalyst

Structure:

**2–4 words**

Always.

---

# Naming Architecture

Every name contains:

## Part 1 — Identity Modifier

Function:

Captures orientation.

Examples:

- Strategic  
- Awakening  
- Visionary  
- Relentless  
- Deep  
- Truthful  
- Patterned  
- Generative  
- Catalytic  
- Future-facing

Source:

Usually signature #1 or #2.

---

## Part 2 — Identity Core

Function:

Captures operational identity.

Examples:

- Architect  
- Builder  
- Catalyst  
- Navigator  
- Operator  
- Originator  
- Guide  
- Synthesizer  
- Guardian  
- Pioneer

Source:

Usually signature #1, #2, or #3.

Core must be the strongest operating behaviour.

---

## Optional Part 3 — Identity Layer

Only if needed.

Examples:

- The Strategic Builder Guide  
- The Pattern Architect Operator

Use sparingly.

Default:

2 words.
Preferred.

# Dominance Rule

Signature #1 has naming priority.

Unless:

Signature #2 and #3 create a stronger synthesis.

Example:

Top 5:

- Builder  
- Truth Seeker  
- Amplifier  
- Architect  
- Guardian

Weak:

Truth Builder

Strong:

Strategic Builder

Builder remains the operational core.

---

# Tension Integration Rule

If the dominant tension is transformational:

Use transformational modifier.

Examples:

- Awakening  
- Rebuilding  
- Emerging  
- Reclaimed

Use when the user is in transition.

---

# Identity Stability Rule

The name must reflect stable identity.

Not temporary emotion.

Never use:

- Burned Out Builder  
- Lost Architect  
- Stuck Catalyst

Temporary states are not identity.

---

# No Literal Stacking Rule

Never stack raw signature names.

Bad:

- Builder Catalyst  
- Pattern Seeker Architect  
- Truth Seeker Amplifier

Weak.
Mechanical.
Non-human.

---

# Brandability Rule

The name should be shareable.

Test:

Would the user say:

“I got The Strategic Builder.”

Good.

Would they say:

“I got The Contextual Finisher.”

Weak.

---

# Memorability Rule

The name must be easy to remember.
Easy to repeat.
Strong rhythm.

### Strong examples

- The Awakening Architect  
- The Strategic Builder  
- The Pattern Catalyst

### Weak examples

- The Contextual Systems Optimizer

Too heavy.

---

# Recognition Rule

The name must feel personally accurate.

Ask:

Would the user immediately recognise themselves?

If not:
Reject.

---

# Name Quality Filter

Before finalising:

## Is it concise?

2–4 words.

---

## Is it memorable?

Easy recall.

---

## Is it identity-level?

Not behavioural only.

---

## Is it emotionally resonant?

Should create internal recognition.

---

## Is it derived from Top 5?

Must be.

---

# Output Format

Always:

**THE [Named Identity]**

Examples:

- THE STRATEGIC BUILDER  
- THE AWAKENING ARCHITECT  
- THE PATTERN CATALYST  
- THE TRUTHFUL OPERATOR  
- THE VISIONARY GUIDE

Consistent formatting.
Always.

---

# Final Test

Before output:

Ask:

- Does this feel like a real identity?  
- Would this feel shareable?  
- Would this create immediate recognition?  
- Would this feel earned?

If no:
Regenerate.

The Named Identity is successful only if the user thinks:

**“Yes. That’s me.”**
