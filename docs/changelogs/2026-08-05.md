## 2026-08-05 — #100 Stage 2: Cover section reorder

Per `docs/briefs/100-cover-reorder-brief.md`. Pure JSX reorder/removal
inside `app/identity/page.tsx`'s Cover block — no data model changes, no
prompt changes, no new components, no CSS file edits.

### Changed
- **`app/identity/page.tsx`** —
  - Context line (`cover.prepared_for · cover.identity_context`) moved from
    below `identity-thesis` to directly under the `<h1>` named-identity
    heading, now rendering *before* the thesis rather than after.
  - Date line (`prepared-for-line` / `reportDate` / `formatDate`) deleted
    outright, not relocated.
  - Constellation Synthesis moved into `.report-cover`, positioned
    immediately after `identity-thesis`. Its standalone `.report-section`
    wrapper (previously the first child of `.report-sections`) was removed
    entirely, not left as an empty shell. The `"CONSTELLATION SYNTHESIS"`
    eyebrow and the `<h3 className="named-identity mb-12">` heading were
    dropped — not rendered anywhere. The `.card` wrapper div was removed;
    `constellation_synthesis.synthesis` now renders as a bare `<p>` with no
    wrapping div and no `className`.
  - `constellation_synthesis.named_identity` is now unused in this file as
    a direct result of dropping the heading — expected per the brief, not a
    bug.
  - Removed now-dead code that only existed to support the deleted date
    line: `reportDate` (derived from `genPhase.createdAt`), the
    `formatDate()` helper, and `MONTHS` (formatDate's only consumer).
    Confirmed via grep that none of the three had any other reference in
    the file before removing them.

### Decisions
- Left `MONTHS`/`formatDate`/`reportDate` removal in scope even though the
  brief only named `reportDate`/`formatDate` explicitly — `MONTHS` became
  transitively dead the moment `formatDate` was removed, so leaving it
  behind would have been an inconsistent partial cleanup of the same dead
  code path.
