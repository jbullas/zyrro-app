## 2026-07-29 — #84/#86(a)/#87 bundled prompt-editing pass (voice, evidence reuse, tagline)

Per `docs/briefs/84-86-87-voice-evidence-tagline-brief.md`: three mechanical
prompt edits to `lib/prompts/identity-report.ts` (`LAYER_2_PROMPT`), bundled
per session decision 2026-07-28 into one round of live-verified regeneration.
`#86`'s part (b) — the automated post-generation phrase-overlap check — is
explicitly out of scope, stays open under #86 as follow-up.

### Changed
- **`lib/prompts/identity-report.ts`**:
  - **C1 (#84)**: added a `### Voice` rule under `## GLOBAL STANDARDS`,
    alongside `### Tone` — write exclusively in second person throughout
    every text field, never refer to the user by name or in third person
    anywhere except `cover.prepared_for` (metadata, not narrative prose).
  - **C3(a) (#86)**: added a `## THE EVIDENCE REUSE RULE` section after
    `## THE EVIDENCE RULE` — (1) forbid literal/near-verbatim reuse of the
    same evidence clause across sections; when sections legitimately share
    an underlying fact, each must surface a different angle (what happened
    / what it reveals / what it costs), never restate the same sentence;
    (2) `secondary_signature_analysis[].analysis` must cite raw evidence
    from the user's actual answers only, never the report's own generated
    write-up of another signature.
  - **C5 (#87)**: rewrote the `### cover.identity_thesis` field requirement
    to require distillation instead of echo — pick one evidence_unit
    (preferring one tagged `source_question` 1 or 13, falling back to
    highest `emotional_weight`), identify its concrete circumstance, and
    reframe it in the report's own synthesizing voice rather than naming
    or lightly rewording the top two primary signatures or
    `identity_rationale`. Added an explicit forbidden-pattern example and a
    constraint against referencing the interview/interaction itself.
- No other files changed.

### Decisions
- **C3 pre-check (required before finalizing wording) — no fabrication
  risk found.** Pulled all 12 real users with a full 13-answer
  `discovery_answers` set. 11 of 12 are substantial (420–1,900 words,
  clearly 8+ distinct behavioral facts each). The one thin set (119 words,
  ~5–6 distinct facts) can still satisfy the rule as scoped, because it
  only requires a different *angle* on a reused fact (what happened / what
  it reveals / what it costs) — that's interpretive rephrasing, not a
  requirement for new unsupported claims, so even the thinnest real input
  doesn't force fabrication. Proceeded without triggering the brief's stop
  condition.
- **Controlled A/B (stop condition: any field outside the three targeted
  areas changes output) — not triggered.** Ran Layer 2 six times against
  the same fixed Detection Engine analysis output (3 original prompt, 3
  edited), plus follow-up trials against a second, independent real
  answer set. Primary/secondary signature selection, scores,
  `domain_profile`, array cardinalities, and `how_you_operate` keys were
  identical between original and edited in every trial. The only
  substantive differences were in the three targeted fields. (Minor
  wording drift in `what_this_report_is` and `cover.named_identity`
  formatting — e.g. "Creative Catalyst" vs "The Creative Catalyst" —
  appeared *within* the original-only trials too, confirming it's
  pre-existing run-to-run LLM non-determinism, not something this edit
  introduced.)
- **C5 (#87) wording — accepted at current compliance level, per
  Miroslav's explicit sign-off (Definition of Done path 3), verbatim:**
  > Miroslav accepted C5 (#87) at current compliance level.
  > `cover.identity_thesis` reliably avoids literal-example copying and
  > avoids restating the top-2 signature names, but on some inputs
  > (confirmed: Jordan's case, 3/3 trials) still compresses adequate
  > concrete evidence into a generic-but-accurate trait sentence rather
  > than the sharper distilled version achieved on other inputs
  > (confirmed: Rowan's case, partial). Root-caused as inconsistent model
  > compliance on already-sufficient evidence_units, not a data-thinness
  > or fallback-logic gap — confirmed via full evidence_unit dump
  > comparison across two distinct real cases. Five prompt-wording
  > iterations did not close the gap; a few-shot approach was identified
  > as the likely next lever but was not attempted, since it reintroduces
  > literal-copying risk and would need its own dedicated verification
  > pass. Accepted as-is for this ticket; revisit only if it proves worse
  > in practice than this test suggests.

  Iteration history behind that sign-off, for anyone revisiting C5 later:
  1. First draft ("scan the user's raw discovery answers... for an insight
     sharper than what you would otherwise generate") — Layer 2 never
     actually receives raw discovery-answer text; `generateIdentityReport`
     only passes the Detection Engine's structured `analysis` object to
     Layer 2 (`lib/generate-identity-report.ts`'s user message is
     `User name: ${name}\nAnalysis: ${JSON.stringify(analysis)}`), so this
     produced no behavior change — the model just kept restating the top
     two signature names.
  2. Rewrote to reference `analysis.evidence_units` tagged by
     `source_question` instead, since that's what's actually in the input.
     Also discovered the fixed test case's Detection Engine output had
     zero `evidence_units` tagged `source_question: 13` — added an
     explicit fallback to the highest-`emotional_weight` evidence_unit.
  3. Still no change — traced it to the model paraphrasing
     `analysis.identity_rationale` (the Detection Engine's own
     signature-derived summary sentence, sitting right there in the same
     input) nearly verbatim. Added an explicit "do not lift
     identity_rationale" instruction plus a worked Weak/Strong example
     pair.
  4. The model started copying the Strong example's literal wording
     verbatim instead (~50% of trials on a second, independent real
     answer set) — a worse defect than the one being fixed. Removed the
     quotable Strong example entirely, kept only a labeled Weak
     (forbidden) example, which eliminated the copying.
  5. On the original fixed case, the model still consistently produced a
     generic-but-accurate trait sentence ("You consistently activate and
     develop others in dynamic, creative environments") instead of a
     concretely-anchored one, despite genuinely concrete `high`-weight
     evidence_units being available and reachable by the fallback logic
     (confirmed via a full evidence_unit dump comparison against a second
     real case where the same wording *did* produce a concretely-anchored
     result in 1 of 2 trials) — root-caused as inconsistent model
     compliance on sufficient evidence, not a prompt-reach problem. Held
     here per the sign-off above rather than continuing to iterate.
