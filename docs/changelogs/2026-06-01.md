### Phase 4 — Generation routes (a113a79)
- app/api/generate-path-options/route.ts:
  guards entitlement + identity report presence;
  upserts artifact (resets to generating if
  exists); fire-and-forget; validates output
  before marking ready
- app/api/select-path/route.ts: records
  path_selections row; returns existing ready
  plan immediately (no regeneration, no cost);
  otherwise calls generatePathPlan.
  Note: path_selections insert uses service-role
  client — table has no insert RLS policy by
  design; all writes are server-side only.
- lib/generate-path-plan.ts: shared function
  (not a public route); resolves chosen option
  and identity report from DB; artifact lifecycle:
  generating/ready → return existing id;
  failed → reset and retry; absent → insert new

### Phase 5 — Pages (7be3ba2)
- /path: 7-state machine matching /identity
  pattern (loading, anonymous, verifying, unpaid,
  generating, ready, failed); auto-kicks
  generate-path-options on first paid visit;
  polls every 3s; ready state renders six-section
  report + 4 option cards with stretch badge;
  confirm dialog before calling select-path;
  routes to /plan on confirmation
- /plan: 7-state machine (loading, anonymous,
  unpaid, no-selection, generating, ready,
  failed); polls plan artifact by
  path_options_artifact_id + path_id; ready state
  renders Plan Frame, Full Path (phase cards with
  milestones + signatures), Start Here (action +
  why), Now Let's Implement It block → /mentor;
  retry calls select-path with active selection
- globals.css: 10 new classes (dialog overlay,
  option card, phase milestones, start-here
  actions)
