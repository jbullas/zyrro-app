## 2026-08-10 — #110: Detection Engine full signatures[] + code-computed Primary/Secondary

Per `docs/briefs/110-detection-categorization-brief.md`. Two related
Detection Engine (Layer 1) defects: `signatures[]` had no completeness
rule in the prompt, so in practice it matched `primary_constellation` 1:1
instead of listing every detected signature; and Primary/Secondary
categorization trusted Layer 1's own `primary_constellation`/
`secondary_signatures` name-array judgment instead of the actual `score`
values, so Secondary could legitimately outscore Primary.

### Changed
- **`lib/prompts/identity-analysis.ts`** (`DETECTION_PROMPT`) — new SCHEMA
  RULES line: `"signatures"` must include every signature with at least 1
  evidence unit anywhere in the narrative, not only the Top 5.
  `primary_constellation`/`secondary_signatures` remain a *selection* from
  that list, not a filter on it. `HARD CONSTRAINTS` (minimum 2 evidence
  units per strong signature) untouched — governs Primary/Secondary
  eligibility, not `signatures[]` membership.
- **`lib/generate-identity-report.ts`** — new exported
  `categorizePrimarySecondary(signatures)`: sorts by score descending,
  returns `{ primary: top 5, secondary: positions 6-8 }`. Called in Step A
  right after `computeDomainProfile`, overwriting
  `analysis.primary_constellation`/`secondary_signatures` before Layer 2
  runs — same "overwrite before Layer 2 sees it" pattern already
  established for `domain_profile`. New `logCategorizationComplianceGaps`
  (log-only, not exported outside this module in the shipped version),

Two live-verification rounds were needed because the first attempt
produced an unexpected regression — recorded here in full rather than

**Round 1 (rejected after live verification):** Set `evidence_analysis` to
a bare `"140–160 words."` and `how_you_operate` to a bare `"120–150

diagnosed as caused by dropping the minimum/target framing itself, not by
the new lower numbers — the bare range read to the model as an upper
bound to respect rather than a target to reach.

**Round 2 (shipped):** Reverted `evidence_analysis` to `"minimum 140
words, target 160 words."` and `how_you_operate` to `"Each minimum 120
words, target 150 words."` — same new numbers, old framing style. Re-ran

for evidence_analysis, 109/120 for how_you_operate). Logged as the honest,
expected result per Miroslav's explicit framing going in ("this is not
expected to achieve full compliance... the point of this revert is that
minimum language empirically pulls output higher, not that it solves the
shortfall outright") — not iterated on further this session.

`domain_profile_summary` kept its "90–120 words, loose guide — content
quality and relevance matter more than hitting an exact count" framing
throughout both rounds (the softer framing was judged correctly targeted
