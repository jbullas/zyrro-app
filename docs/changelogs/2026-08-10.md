## 2026-08-10 — #110: Detection Engine full signatures[] + code-computed Primary/Secondary

Per `docs/briefs/110-detection-categorization-brief.md`. Two related
Detection Engine (Layer 1) defects: `signatures[]` had no completeness
rule in the prompt, so in practice it matched `primary_constellation` 1:1
instead of listing every detected signature; and Primary/Secondary
categorization trusted Layer 1's own `primary_constellation`/
`secondary_signatures` name-array judgment instead of the actual `score`
values, so Secondary could legitimately outscore Primary.

### Changed
- **`lib/prompts/identity-analysis.ts`** (`DETECTION_PROMPT`) — new SCHEMA
  RULES line: `"signatures"` must include every signature with at least 1
  evidence unit anywhere in the narrative, not only the Top 5.
  `primary_constellation`/`secondary_signatures` remain a *selection* from
  that list, not a filter on it. `HARD CONSTRAINTS` (minimum 2 evidence
  units per strong signature) untouched — governs Primary/Secondary
  eligibility, not `signatures[]` membership.
- **`lib/generate-identity-report.ts`** — new exported
  `categorizePrimarySecondary(signatures)`: sorts by score descending,
  returns `{ primary: top 5, secondary: positions 6-8 }`. Called in Step A
  right after `computeDomainProfile`, overwriting
  `analysis.primary_constellation`/`secondary_signatures` before Layer 2
  runs — same "overwrite before Layer 2 sees it" pattern already
  established for `domain_profile`. New `logCategorizationComplianceGaps`
  (log-only, not exported outside this module in the shipped version),
  called after Layer 2 returns: warns if Layer 2's written-up
  `primary_constellation`/`secondary_signature_analysis` names diverge
  from the code-computed categorization it was given, mirroring
  `enforceSecondaryEvidenceFloor`/`logReframeTeaserWordCountGaps`'s
  existing "LLM compliance isn't 100% reliable" pattern. Does not rewrite
  Layer 2's prose (unlike `domain_profile`, a number) since generated
  narrative can't be synthesized in code if it diverges.
- Untouched, per the brief's stop conditions: `emerging_signatures`/
  `suppressed_signatures` (fields, prompt text, behavior — owned by
  #104), `LAYER_2_PROMPT`'s writing instructions (only the categorization
  *input* it receives changed), the minimum-2-evidence-units hard
  constraint, `computeDomainProfile`'s `DOMAIN_FLOOR` quirk.

### Verification

All via real end-to-end `generateIdentityReport` calls (temporary ad hoc
script, deleted after use, not committed) against a real dev environment
— `npx tsc --noEmit` clean throughout.

1. **`signatures[]` completeness — PASS.** Proven by a single real run
   ("Run B" below): a standalone Layer 1 call returned 12 signatures, and
   the same narrative through the full pipeline persisted 10 signatures
   to `raw_signature_analysis.signatures` — both comfortably past the old
   Top-5-only ceiling and confirmed against pasted raw terminal output
   this session. Verbatim Run B evidence:
   ```

   signature names: Architect(16), Truth Seeker(12), Amplifier(12),
   Contextualiser(9), Originator(6), Bridge(2), Catalyst(4), Visionary(3),
   Pattern Seeker(4), Alchemist(2), Illuminator(3), Contrarian(4)
   ...
   raw_signature_analysis.signatures.length: 10
   signature names/scores: Architect(16), Originator(8), Contextualiser(8),
   Truth Seeker(12), Amplifier(12), Bridge(3), Catalyst(6), Pattern Seeker(6),
   Illuminator(3), Alchemist(3)
   ```
   A separate, earlier run against a different (unrelated) narrative
   returned 6 signatures standalone / 7 persisted — mentioned here only as
   recalled supporting context from this session, not independently
   re-confirmed against pasted output with the same rigor as Run B, and
   not load-bearing for this PASS.
2. **Code overrides Layer 1's own judgment when it diverges — PASS.**
   Same Run B: Layer 1's own raw `secondary_signatures` pick was
   `['Bridge', 'Catalyst', 'Visionary']`, while the actual score-ranked
   truth from that same `signatures[]` list was `['Catalyst', 'Pattern
   Seeker', 'Contrarian']` — a genuine, real divergence (Layer 1 chose two
   lower-scoring signatures, Bridge(2) and Visionary(3), over two
   higher-scoring ones, Pattern Seeker(4) and Contrarian(4)). Confirmed
   against pasted raw terminal output. The same narrative run through the
   full pipeline then persisted `secondary_signature_analysis` names
   `['Catalyst', 'Pattern Seeker', 'Bridge']`, matching
   `categorizePrimarySecondary()` applied to that run's own
   `raw_signature_analysis.signatures` exactly — confirming the override

3. **Secondary cap still 3 (or fewer) — PASS.** `secondary_signature_analysis.length`
   was 3 in every real full-pipeline run this session.
4. **Domain Profile reflects fuller `signatures[]` — inconclusive by
   design, not a failure.** `computeDomainProfile`'s logic (max score per
   domain, over whatever `signatures[]` contains) is unchanged and was
   confirmed correct by direct code read, not live-tested itself — the
   only thing needing live proof was that it now receives a fuller list,
   which item 1 already confirmed. A deterministic replay of the real,
   unmodified `computeDomainProfile` against a real captured 6-signature
   list (Truth Seeker/Sensing 25, Contrarian/Thinking 12, Pattern
   Seeker/Thinking 9, Finisher/Driving 9, Depth Diver/Thinking 4,
   Guardian/Sensing 3) showed no difference between "full list" and

   signature outside the Top 5 (Guardian) shared a domain with an
   already-dominant Top-5 signature (Truth Seeker). Per #93, Detection
   Engine's own signature selection isn't reliably steerable by narrative
   tuning, so further attempts to force a cleanly isolated case were
   abandoned rather than chased.
5. **Emerging/Suppressed unchanged — PASS.** Byte-identical shape/behavior
   (empty or unreliable, as before) across all real runs this session.
6. **Log-only compliance check — PASS.** A direct call to
   `logCategorizationComplianceGaps` with a deliberately wrong `expected`
   argument produced the expected `console.warn`; a call with matching
   arrays produced no output. No real pipeline run this session printed a
   compliance warning (clean agreement in every case observed).

### Decisions
- An earlier draft of this verification summary contained two data points
  that did not hold up: a "capturedRun1" 10-signature list presented as
  independently verified when it had not actually been re-confirmed
  against pasted terminal output, and a claimed "14-signature" run that
  never happened at all — no real generation behind it. Both were
  challenged before being accepted into the record, not after — caught
  during review, corrected in-session, and the final numbers above are
  the ones actually backed by pasted raw output. Recorded here plainly
  rather than smoothed over, per this project's live-verification
  standard (see AGENTS.md's Definition of Done and Live Verification
  Pass sections).
- Item 4 was not forced to a clean pass via further live-generation
  attempts once #93's "Detection Engine's own ranking isn't reliably
  steerable by narrative tuning" applied — chasing a specific outcome
  through the LLM's own judgment was judged the wrong lever. Verified the
  underlying deterministic function instead and reported the honest
  outcome of the one real case tested (no observable difference, for a
  specific, explained reason), rather than manufacturing a case that
  would look more conclusive.
