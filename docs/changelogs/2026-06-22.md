## Decisions

- **Branch confirmed unreachable before deletion.** The only caller (`app/start/page.tsx`)
  always calls `supabase.auth.signUp()` immediately before posting to the route, so
  `user_id` is always a brand-new UUID with no prior artifacts. If sign-up fails the
  function returns early and the route is never called.
- **No constraint added this session** — deferred to a separate task. The correct form
  is a partial unique index scoped to `identity_report` only:
  `UNIQUE(user_id) WHERE type = 'identity_report'`. A full `UNIQUE(user_id, type)` would
  break `path_plan` / `path_options` rows where users legitimately have multiple artifacts
  of the same type.

## Changed (session 3)

- Added `proxy.ts` (project root) and `utils/supabase/middleware.ts` — session-refresh
  proxy using the Next.js 16 `proxy.ts` / `export function proxy(...)` convention.
  Calls `getUser()` immediately after client creation to trigger a token refresh on
  every matched request; refreshed cookies are carried onto the response via `setAll`.
  Matcher excludes `_next/static`, `_next/image`, `favicon.ico`, and image file
  extensions. Build clean, no TS errors. Preview verified: login, navigation, and
  auth/callback all work; a cleared session degrades cleanly to logged-out.

## Decisions (session 3)

- **Refresh-only scope.** No redirect or route-protection logic in the proxy — the app
  gates auth at the page/route level and adding middleware redirects risks conflicting
  with those gates. That's a separate, deliberate decision if wanted later.
- **Per-page session recovery left in place.** The `refreshSession()` retry on the
  identity page and equivalent guards elsewhere are not removed yet. Once the proxy is
  confirmed working in real use, simplifying those is a clean follow-up.
