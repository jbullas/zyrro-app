### Decisions
- **Meta-bundle placement**: kept below the three status cards (only
  Identity exists yet). The brief flagged this as unspecified with "below"
  as a reasonable default and asked for it to be a judgment call noted
  here rather than assumed silently — no code signal argued for a
  different position, so went with the default.
- **No shared `DashboardCard` loading/empty wrapper component.** First
  draft built one (generic loading/empty/content wrapper reusing
  `.mentor-list-empty`), but the user redirected: Identity (badge+chart),
  Momentum (dial+counts), and Project (header+lists) don't yet share enough
  shape to justify a real abstraction — premature to build one component
  for a pattern only one card currently demonstrates. Reverted to inlining
  the three-state branching directly in `IdentityCard.tsx`'s JSX, still
  using the same `.card` + `.mentor-list-empty` convention the existing
  meta-bundle section already established, so the *convention* is
  consistent and copyable even without a component boundary enforcing it.
  Revisit extraction once a second real card (Momentum) shows the same
  loading/empty shape actually repeating.
- Dashboard's Identity card distinguishes two empty sub-states behind one
  `.card`: no `identity_report` row at all ("complete the questionnaire")
  vs. a row that exists but isn't `status = 'ready'` ("still being
  generated"). Not strictly required by the brief (which only asked for
  "an appropriate empty/pending state"), but both scenarios are named
  explicitly in the brief's prose and cost nothing extra to distinguish.

### Verification
- `npx tsc --noEmit` and `npm run build` both clean.
- Live-verified with `scripts/run-verification.mts` (ad hoc script, not
  committed — one-off per ticket): bootstrapped a synthetic user, seeded a
  `ready` `identity_report` artifact with a distinctive `domain_profile`
  and 5 ranked primary signatures (top: Builder/Driving/23). Confirmed the
  dashboard card renders the correct named identity, thesis, and badge icon
  collapsed by default; after clicking "Show identity profile," confirmed
  the chart canvas mounts and the bar-list order/scores match; cross-checked
  both against `/identity` for the same seeded content and got identical
  values. Also verified the true no-artifact-row state.
- Honest accounting: four failures surfaced while iterating on the
  verification script itself. All four turned out to be flaws in the
  *script*, not in the shipped product code — the underlying rendering was
  already correct on the first run in every case. Recorded here in full
  rather than folded silently into "fixed and passing," since a clean final
  run doesn't by itself distinguish "found and fixed a real bug" from
  "found and fixed a bad assertion":
  1. **Badge assertion, false failure.** Checked
     `.identity-badge-wrap svg` (a descendant selector) expecting count 1.
     `IdentityBadge` legitimately renders two `<svg>`s at different depths —
     the shield itself, and the Tabler icon component nested one level
     deeper inside it — so the count was always 2, not a missing badge. A
     debug HTML dump confirmed both were present and correct (right
     gradient, right icon) from the very first run. Fixed by asserting the
     child combinator `.identity-badge-wrap > svg` (count 1, the shield
     only) plus a separate, more useful check that
     `.identity-badge-icon .tabler-icon-hammer` is present — actually
     confirming the icon matches the seeded top signature, which the
     original assertion never checked at all.
  2. **Heading assertion, false failure.** Checked
     `textContent('.report-cover h1')` for the substring
     `'Strategic System Architect'`. `app/identity/page.tsx`'s
     `splitNamedIdentity()` renders the name as
     `{nameLine1}<br />{nameLine2}`; `textContent` ignores `<br>` entirely
     and concatenates the surrounding text nodes with no space, producing
     `"THE Strategic SystemArchitect"` — the substring check failed even
     though the heading was rendering correctly. Fixed by reading
     `.innerText()` instead (respects rendered line breaks) and normalizing
     whitespace before an exact-equality comparison, which is also a
     stricter check than the original substring match.
  3. **No-artifact-row state, environmental, not a bug.** A "fresh" test
     user still showed the "still being generated" (pending) message
     instead of "complete the questionnaire" (no row at all), because
     `bootstrapTestUser` drives the real `/auth/callback` route, which
     fires `kickoffIdentityGeneration()` in the background for any new
     user and inserts its own `generating` artifact row — a known,
     documented side effect (local memory
     `reference_local_test_auth_bootstrap`). Both card states are
     legitimately reachable and both rendered the right copy; the test
     just needed to explicitly delete that auto-created row to exercise
     "no row at all" specifically, as the brief's verification section
     asks for.
  4. **Chart screenshot, test-timing artifact.** A full-page screenshot
     taken immediately after the chart's `<canvas>` appeared in the DOM
     caught Chart.js mid-animation (its default grow-from-center effect),
     so the polygon looked collapsed to a point. Not related to the
     mount-on-expand behavior itself — the canvas was already correctly
     sized and mounted; it just hadn't finished drawing. Added a short wait
     for the animation to settle before screenshotting; re-verified the
     chart renders with correct per-domain point positions matching the
     seeded `domain_profile`.
  - Net result: zero real bugs found in the shipped implementation via live
    verification. All four issues were properties of the verification
    script or the test environment, not of `IdentityBadge`,
    `DomainRadarChart`, `PrimarySignatureBars`, or `IdentityCard`.
