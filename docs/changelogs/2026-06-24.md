## 2026-06-24 — Session 3

### Changed
- Added `20260530000001_profiles_baseline.sql` — captures `public.profiles` (columns, PK, plan CHECK, FK→auth.users ON DELETE CASCADE, RLS enabled, 3 policies: INSERT/SELECT/UPDATE, BEFORE UPDATE trigger calling `public.set_updated_at()`).
- Added `20260530000002_conversations_baseline.sql` — captures `public.conversations` (columns, PK, status CHECK, FK→profiles ON DELETE CASCADE, `idx_conversations_user_id`, RLS enabled, 4 policies: DELETE/INSERT/SELECT/UPDATE, BEFORE UPDATE trigger).
- Updated the prerequisite comment in `20260531000000_artifacts_baseline.sql` to reference the two new migration filenames by name.
- Investigated `public.memory` (read-only, no migration written — see Decisions).

### Decisions
- `profiles` first (`20260530000001`), `conversations` second (`20260530000002`): driven by the FK constraint `conversations.user_id → profiles(user_id) ON DELETE CASCADE` — the referenced table must exist first.
- Both pre-dated into the `20260530…` window so the fresh-build order is: shared_functions → profiles → conversations → artifacts.
- Idempotency pattern matched exactly to the artifacts baseline: `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, DO-block-wrapped policies, `CREATE OR REPLACE TRIGGER`.
- Neither baseline applied to the live DB — `IF NOT EXISTS` makes both a no-op since the tables already exist. Capture is a repo concern only.
- **`memory` disposition pending human decision.** Findings:
  - Shape: `user_id` (uuid PK, FK→profiles ON DELETE CASCADE), `summary` (text, nullable), `key_patterns` (jsonb, nullable), `created_at`, `updated_at`.
  - Indexes: PK + `idx_memory_user_id` on `user_id`.
  - RLS enabled (not forced); 4 policies (DELETE/INSERT/SELECT/UPDATE, all `auth.uid() = user_id`).
  - Trigger: `set_memory_updated_at` BEFORE UPDATE → `public.set_updated_at()`.
  - Row count: **0**.
  - App code references: **none** — no hits in `lib/`, `app/`, `types/`, or any `.sql` migration for `from('memory')`, `from("memory")`, or the string `memory`.
  - Conclusion: the table exists in live with full RLS and a trigger, but has never been written to and is invisible to the application. Options: capture as a baseline (symmetry), drop it (dead weight), or document and defer. Call is the human's.
- **Decision:** memory table left in place, uncaptured — orphaned schema from the unbuilt mentor-conversation-memory feature; revisit (capture vs drop vs reshape) when /mentor scope is defined.
- **Decision:** memory table kept — Zyrro will need a memory capability of some form; the owning surface (/mentor or other) is not yet decided. Table is a correct per-user store to adopt or reshape when that's defined.
