## 2026-08-04 — #62 persist full Detection Engine output onto identity_report

Per `docs/briefs/62-persist-detection-engine-output-brief.md`. Layer 1's
full output (`signatures[]` + all 4 categorization lists) was being
discarded in-memory once generation completed — only Layer 2's report made
it to `artifacts.content`. Nothing downstream (Reframe/#43, #100's planned
Emerging/Suppressed cards, mentor longitudinal tracking, ad hoc review)
could access it after the fact.

### Changed
- **`lib/artifact-schemas.ts`** — added optional
  `raw_signature_analysis` to `IdentitySignatureReportArtifactContent`:
  `{ signatures, primary_constellation, secondary_signatures,
  emerging_signatures, suppressed_signatures }`, sourced verbatim from
  Layer 1. Optional since existing reports predate the field. Widened
  `schema_version` to `"1.0" | "1.1" | "1.2"` (type-level only — no code
  path currently emits `"1.2"`; Layer 2's prompt still literally emits
  `"1.1"`, unchanged by this ticket).
- **`lib/generate-identity-report.ts`** — in `generateIdentityReport`'s
  Step C, attaches `report.raw_signature_analysis` from the already-in-scope
  `analysis` object (no new API call) right before the `content: report`
  update.

### Decisions
- No migration — additive JSON field on an existing JSONB column, per the
  brief.
- No backfill — Layer 1 is confirmed non-deterministic even at temperature
  0 (#93), so re-running it against stored discovery answers would write
  plausible-looking but non-original data onto historical reports. Existing
  reports simply won't have `raw_signature_analysis`.
- No UI rendering (that's #100 Stage 2, still paused) and no #43 folding —
  out of scope here, both unblocked by this ticket.

### Verification
- `npx tsc --noEmit` and `npm run build` both clean.
- **Live end-to-end**, 2 real generations via `withVerificationSession`
  (`scripts/run-verification.mts`) with real discovery-answer sets, driving
  the actual `/auth/callback` → `kickoffIdentityGeneration` →
  `completeDiscovery` → `generateIdentityReport` path with real OpenAI
  calls — not seeded content. Confirmed via direct Supabase read of the
  resulting `artifacts` row for both users:
  - `raw_signature_analysis` present and populated (`signatures.length: 5`
    in both runs, real `score`/`domain`/`frequency`/`intensity`/
    `score_band`/`confidence`/`supporting_evidence_indexes` per entry).
  - Existing fields untouched: `primary_constellation` (report, length 5),
    `domain_profile`, `derived_from_signature_analysis` all present and
    correctly shaped, `schema_version` still `"1.1"` — a pure addition.
  - Both test users had empty `emerging_signatures` and
    `suppressed_signatures` — no live signal yet on how often those lists
    are non-empty; useful for #100 Stage 2 to know this wasn't exercised
    here.
- Ad hoc verification script run from `scripts/verify-62-tmp.mts`, deleted
  after, not committed — confirmed via `git status`.
- Not committed/pushed yet this session.
