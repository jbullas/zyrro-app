## 2026-08-04 — #102: re-scope constellation_synthesis as a short extension of identity_thesis

Per `docs/briefs/102-constellation-synthesis-rescope-brief.md`. Re-scoped
`constellation_synthesis.synthesis` in `lib/prompts/identity-report.ts`
(Layer 2) from a 300-350 word field describing operating/decision/energy/
leadership/relational style (fully redundant with `how_you_operate`) down
to a 60-90 word extension of `cover.identity_thesis`, matching #100 Stage
1's placement of this field immediately after Identity Thesis inside
Cover. Started as prompt-only per the brief, but ended with a small,
explicitly approved scope expansion into a code-level backstop after
prompt-wording alone proved insufficient — full story below.

### Changed
- **`lib/prompts/identity-report.ts`** — `### constellation_synthesis`
  rewritten: minimum 60 words, target 75-90, hard ceiling 95; structured as
  exactly 3 sentences each with a distinct job (a new concrete behavior, a
  second distinct way the pattern shows up, a present-tense "still true
  now" observation or tension), explicit prohibition on sharing sentence
  1's verb/object with `identity_thesis`, explicit prohibition on
  restating the named identity anywhere in the synthesis (not just the
  opening), explicit prohibition on naming individual signatures or
  describing operate-style categories. Added an approved reference example
  (with a separate, non-inline mapping onto the 3-sentence structure) and
  a "disqualified patterns" section describing (not quoting verbatim,
  after round 3's finding below) real failure shapes to avoid.
  `STRUCTURAL CONSTRAINTS`'s `constellation_synthesis` line updated from
  "minimum 300 words" to "minimum 60 words (target 75-90)".
- **`lib/generate-identity-report.ts`** (new, small scope expansion beyond
  "prompt-only" — see Decisions) — added
  `enforceConstellationSynthesisNonOverlap()`, called in
  `generateIdentityReport` right after `enforceSecondaryEvidenceFloor`.
  Detects any shared run of 4+ consecutive words (case-insensitive,
  punctuation-insensitive) between a `constellation_synthesis.synthesis`
  sentence and `cover.identity_thesis`, and drops that sentence outright
  rather than trying to rewrite it. Logs a `console.warn` only if this
  empties the synthesis entirely (every sentence overlapped); otherwise
  silent, since a partial drop is the expected, working case.

### Decisions
- **4-word overlap threshold, not the "5+" originally proposed.** Before
  wiring the code guard in, ran a standalone test of the overlap-detection
  logic against this session's actual Run 1 failure text ("transform chaos
  into order" lifted verbatim from `identity_thesis`) — that phrase is
  itself only 4 words, so a 5-word threshold would have let the exact
  motivating failure straight through. Confirmed 4 catches it with no
  false positive against an unrelated, non-overlapping synthesis sentence
  before committing to it. The verification script's own regression check
  was changed to match (4, not 5) for the same reason — a weaker script
  check wouldn't actually test the guarantee the code makes.
- **Code-level backstop, approved scope expansion (2026-08-04, Miroslav).**
  4 distinct prompt-wording rounds — first-sentence-only non-overlap rule,
  then any-sentence rule, then a full structural 3-sentence template — were
  tried across 8 real end-to-end generations before this. Every round
  fixed some symptoms (named-identity restatement and signature-name
  leakage were solid from round 2 onward) but verbatim or near-verbatim
  reuse of `identity_thesis`'s own key phrase kept surviving somewhere in
  the paragraph regardless of wording. This is the same "inconsistent
  model compliance on a clear instruction" pattern already documented for
  `enforceSecondaryEvidenceFloor` (three prompt rounds, then closed in
  code) — given that precedent, a 5th prompt-only round was judged unlikely
  to close it reliably, so the ticket's "prompt-only change" stop condition
  was explicitly relaxed for this one, narrow, prompt-resistant,
  code-checkable failure profile.
- **No attempt to rewrite/regenerate the dropped sentence.** There's no
  deterministic way to turn a restatement into new content in code — only
  to remove it. Accepted tradeoff: the backstop firing means the synthesis
  can land under the 60-word floor (observed: down to ~38-44 words when a
  sentence is dropped from an original 3), in exchange for guaranteeing no
  thesis restatement ever reaches the page. Word-count compliance was
  judged the lower priority of the two requirements.

  3. Widened named-identity check to scan the full text (not just the
