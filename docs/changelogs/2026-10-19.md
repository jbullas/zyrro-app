### Decisions

- **Redirects in `proxy.ts` after `updateSession()`:** one place covers all sub-paths and runs
  before any client page code. `utils/supabase/middleware.ts` stays untouched.
- **A: /account with Path off:** no Upgrade button (it sells Path). The Plan row reads "Full
  Identity report" for paid users, "Free plan" otherwise.
- **B: share-link ready check on the service role:** otherwise the RLS rule would stop unpaid
  users sharing their free hero.
- **C: IdentityCard and /path read through the route.** The locked projection carries
  `reframe_teaser`, which isn't a locked section.
- **D: the identity checkout takes the user from the session.** The $49 checkout is left as it
  was, with `user_id` still coming from the request body.
- **Extra UPDATE policy:** "Users can update own artifacts" would let a user re-type an
  `identity_report` row, then read it.
- **Notice:** a `.card` with a green check, so no new class.
- **Lock links:** left-aligned (wrapped in a `<div>`), because `.btn-link` centres in a flex column.
- **Strip bullets:** a white check icon, because `.bullet-dot` and `.bullet-item` are too dark for
  the gradient.
- **Item 4 price swap via the dev server's env, not `.env.local`:** same effect, and the file was
  never edited back and forth.
- **#162 Definition of Done:** every path in the brief's live-verification list was verified
  this session (option 1). Nothing was handed off or risk-accepted.

### Findings

- **The Stripe sandbox's only webhook endpoint is Vercel Preview** (`we_1U91MJD1x3GEDcZijaiJ17bb`),
  which shares the Supabase DB. Every local test Checkout is also delivered there and granted with
  whatever code Preview runs.
  - Before `37d54ca` was deployed, this gave $19 test buyers an extra `onetime_payment`.
  - It's fixed now that Preview runs step 4.
- **PostgREST rejects a WHERE-less UPDATE** ("UPDATE requires a WHERE clause"), so the filtered
  form is the real client-side attack path.
