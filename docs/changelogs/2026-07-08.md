### Decisions

- Commit granularity for pass 2: Item 0 committed alone (doc-only); items 1–4 committed together. The brief allowed grouping "cleanup" items, and in practice items 1–4's `globals.css` edits interleaved across the same regions (rules added, moved, and removed in overlapping areas) — true per-item separation would have risked a broken intermediate commit.
- Caught a real bug before committing, not after: the new `.gap-*`/`.mb-*` utility classes, first placed near the token definitions at the top of `globals.css`, silently lost CSS cascade ties against component classes with their own `margin-bottom` at equal specificity (e.g. `.section-title`'s `margin: 0 0 16px 0` beat `.mb-8`'s `margin-bottom: 8px` because it came later in the file). `.mb-8`/`.mb-32` computed to `16px` instead of `8px`/`32px` wherever stacked with `.section-title` — invisible in a screenshot (16px vs 8px reads as "looks fine"), only caught via `getComputedStyle` checks. Fixed by moving the entire utility-class block to the end of the file, where it now always wins cascade ties against component classes regardless of which one it's paired with.
- User redirected two mid-session decisions rather than letting the brief's literal wording stand: (1) Item A's `.mentor-md-p` pre-wrap change was implemented as a scoped modifier instead of editing the shared rule, once the mentor-page markdown soft-break risk was surfaced; (2) Item 3's `--radius-input` token was dropped in favor of reusing the existing `--radius-md` token after being asked to check for a duplicate before adding it.
- Both flagged high-visual-risk items (Chart.js sizing, textarea consolidation) were live-verified with actual screenshots and computed-style checks, per standing practice and explicit mid-session request for the textarea specifically.
