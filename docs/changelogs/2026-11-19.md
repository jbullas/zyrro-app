### Decisions

- **The #181 naming design replaces Jeff's original spec (Miroslav's call).** Scoring names by countable rules (rare letters, syllables, double letters, a vowel ending) gave too few strong names and, in round one, code that miscounted. Names are now built from concrete words of the chosen path, checked by code, filtered for bad meanings and brands, and shown 5 at a time at random, with no scores and no rationale.
- **gpt-4.1 at temperature 1.0 makes the names.** In the model comparison it gave the most name-like new words. gpt-6.1-sol repeated safe compounds, and gpt-6.2-astra wrote readable phrases rather than names. Source words and the filter stay on gpt-6.1-sol.
- **Path vs project naming model.** The path is the chosen option, shown by its descriptive name, which never changes. The project is what the user builds on it, with an optional name they can give, change or remove. The descriptive name is the heading on "Your path" and `/plan`, and the project name is a line under it.
- **Plans are written with the descriptive path name only, never the project name**, so renaming the project can't leave the Plan text stale. Existing Plans stay as they are.
- **Naming state lives in `path_choice` content, not a new artifact type**, to avoid a migration. Every writer goes through a version-checked write, so a typed save made while a set is generating keeps both.
- **Ordinary English words:** `wordlist-english` levels up to 60 (about 75,000 common words). Rarer words aren't counted, so a name isn't dropped for matching an obscure word.
- **Names are 7 letters or fewer** (the picks in testing were all 5 or 6), and fresh sets from "Your path" are limited to **3 per user per rolling 24 hours**.
