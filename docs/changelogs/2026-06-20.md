- **`app/identity/page.tsx` — stale session recovery (brief: identity-stale-session-recovery)**
  - `init()`: after `getUser()` misses, attempt one `refreshSession()` before declaring the user anonymous. On `discovery_answers` count error, refresh and retry once; if still errored, route to `/login` rather than falling through to `no-questionnaire`.
  - `loadArtifact()`: capture `error` from the artifacts query. Auth/transport failure now routes to `/login`; genuine no-row (`!data`, no error) still sets `no-questionnaire`.
  - Wired `useRouter` from `next/navigation` for programmatic navigation (added to component and to the effect's dep array).
  - Removed the DEV-ONLY "Regenerate report" button and `handleRegenerate` callback. Dropped the now-orphaned `userId` state (only `handleRegenerate` read it; `setUserId` call removed from `init()`).
  - Build clean (`next build`, no TS errors). Two pre-existing lint issues (`domain_profile` unused in render destructuring; unescaped entity) left untouched — not exposed by this change.
  - **Verified on Preview**: DevTools network request blocking of `*/rest/v1/*` (auth still up) confirmed a present-but-failing session correctly routes to `/login` instead of showing the no-questionnaire screen.

## Decisions

- **Stale session → `/login`, never → `anonymous`**: design rule enforced to prevent a second auth user being created for the same email. A refreshable session is salvaged; an unrecoverable one re-authenticates.
- **`generate-report` route left untouched**: the route's existing-artifact "blank then regenerate" branch is now unreachable from the app (Regenerate button gone), but cleaning it up is deferred — harmless dead code, out of scope per the brief.
- **`userId` state removed**: only `handleRegenerate` read it; `user.id` is already in scope inside `init()` and passed directly to `loadArtifact`. Lint flagged it immediately after the callback removal.
