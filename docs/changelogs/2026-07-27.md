## 2026-07-27 — #81 render `scoring_explanation` in Signature Profile

### Changed
- **`app/identity/page.tsx`**: added `signature_profile_summary?: {
  scoring_explanation: string }` to the `IdentityReport` interface,
  destructured it from `report`, and render it as a plain `<p>` directly
  under the "SIGNATURE PROFILE" eyebrow in Section 3, above the
  `PrimarySignatureBars` card — matching Section 2's "What This Report Is"
  typographic convention (plain paragraph, no new component). Field is
  optional and only rendered when present, so an artifact missing it
  degrades to no paragraph rather than a crash. No changes to
  `PrimarySignatureBars`, `DomainRadarChart`, the secondary-signature list
  markup, D5, the scoring model, or any prompt file — per the brief's stop
  conditions.

### Decisions
- **Made `signature_profile_summary` optional in the `IdentityReport`
  interface rather than required.** The brief's own verification step asked
  for a safe-fallback check against an artifact missing the field; every
  live `ready` row currently has it, but nothing guarantees that forever, so
  the type reflects the real contract rather than assuming presence.
