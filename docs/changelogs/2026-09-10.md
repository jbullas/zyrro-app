## 2026-09-10 — #134 Slice 2: Checkpoint 2 "Options" shipped and live-verified

### Changed

- New `path_options_session` artifact type (migration
  `20260910000000_path_options_session.sql`). Unlike `path_direction_session`
  (Slice 1), this type has a real background-generation state — the initial
  4 options and each +2 refine round are real LLM calls — so its status
  vocabulary reuses `path_checkpoint_session`'s own
  `generating`/`awaiting_checkpoint`/`complete` shape rather than Direction's
  `in_progress`/`complete`, and the race guard follows that same precedent:
  a partial unique index on `(user_id) WHERE status = 'generating'`,
  protecting the creation race only — re-claiming generation on an existing
  row is a separate conditional-UPDATE guard
  (`claimGeneration`, `lib/path-options-session.ts`). `content.candidates` is
  append-only across the session's life (§7 of the brief — the reason this
  isn't a `path_checkpoint_session` migration at all).
- `lib/path-options-session.ts` — data-access layer:
  `startOrReuseOptionsSession`, `claimGeneration`, `appendCandidates`,
  `recordSelection` (defensively rejects a `candidate_id` not among the
  session's own real candidates).
- `lib/prompts/path-options-session.ts` + `lib/generate-path-options-session.ts`
  — the generation module: the LLM call, output validation, and the two hard
  checks the brief requires running in code rather than trusting prompt
  compliance (`enforceSecondaryEvidenceFloor`/
  `enforceConstellationSynthesisNonOverlap`'s established pattern), plus the
  over-generate-N+2/take-first-N/one-bounded-retry/hard-fail control flow.
  Three real bugs surfaced by testing against real generated content, not
  assumed correct from the design:
  - **Stemmer bug**: the naive suffix-stripper's `-es` branch fired on any
    word ending in `-es`, not just true sibilant plurals — `cycles` (`cycle`
    + `s`, a word already ending in `e`) stripped to `cycl` instead of
    `cycle`, silently breaking the "close lexical variant" match for
    must-avoid phrases like "long review cycles." Fixed to only fire the
    2-char strip for a genuine sibilant plural (checked via the preceding
    letter), falling through to the 1-char strip otherwise.
  - **Must-avoid check had no negation awareness**: the brief's own
    content-bar point 4 ("how it avoids every must_avoid") reliably produces
    compliant sentences like "inherently avoids ambiguous requirements" —
    a pure phrase-presence check can't tell that apart from an actual
    violation. First real generation run: 12/12 drafts wrongly rejected.
    Fixed with a bidirectional negation-cue window (confirmed unmodified
    coverage wasn't enough — also missed `sidesteps micromanagement`,
    a cue word never in the vocabulary, and `"[phrase] is eliminated"`,
    a cue word *after* the phrase the original backward-only window
    couldn't see).
  - **Material-difference threshold too low**: `8` words flagged two
    genuinely different real options as duplicates purely because they
    shared stock connector phrasing the content bar's rigid structure
    induces across every option (e.g. "aligns with your ideal life by
    allowing you"). Raised to `14`, calibrated against that real captured
    pair plus the existing true-16-word-duplicate fixture.
- `app/api/path-options/route.ts` — GET bootstraps/resumes (loads
  `identity_report` + a completed `path_direction_session`, 409s if Direction
  isn't done, defensive server-side check matching `/api/path-direction`'s
  own posture) and kicks off the initial 4 via `after()`; also resumes a
  previously-**failed** session (found and fixed after the first version
  only ever kicked off generation for a brand-new row, never a crashed one —
  `claimGeneration`'s same conditional-UPDATE pattern guards concurrent
  resume attempts). POST `action: 'refine'` (claims generation, enforces the
  8-cap server-side too) and `action: 'select'` (synchronous, no LLM call).
- `lib/use-path-options.ts` — confirmed (not assumed)
  `useCheckpointSessionStatus` is reusable completely unmodified: it's
  generic over any `artifacts` row by id, and the one real limitation found
  (its `'complete'` phase carries no content) doesn't matter here since
  Checkpoint 2's `awaiting_checkpoint → complete` transition happens
  synchronously via `submitSelect`'s own response, never through polling.
  `retry()` deliberately diverges from `usePathDirection`'s literal pattern
  with an explicit `bootstrapKey` counter — copying Direction's retry as-is
  wouldn't actually re-invoke its bootstrap effect on a failed fetch, since
  that effect's dependencies don't change value in that case.
- `components/OptionsFlow.tsx` — cover, generating-state view, the 4/6/8-card
  grid, tentative-select → comments → confirm sub-flow, free-text refine
  (hidden at the 8-cap), terminal summary. Built on two pieces recovered
  from git history rather than reinvented: the Stage D spinner copy
  (commit `faedc73`, removed in Slice 1's cleanup) for the generating states
  — with a now-genuinely-working retry, since the route resumes failed
  sessions — and the **pre-#129** 4-card layout (commit `7be3ba2`), not
  Stage D's version, which used one shared button below a stack of cards —
  exactly the pattern brief §4 calls out as wrong. `.option-card-sigs` (that
  recovered pattern's signature-chip row) deliberately not reused — CP2
  candidates carry no `signatures_engaged` field to put there.
- `app/path/page.tsx` — `OptionsFlow` replaces `DirectionFlow`'s terminal
  `'complete'` branch entirely, activated via `usePathOptions(direction.step
  === 'complete')`, same gating convention as `usePathDirection`'s own
  `active` param. No new `PageState` value. `DirectionFlow`'s own internal
  `'complete'` branch is now unreachable dead code — flagged in a comment,
  not deleted this slice.
- `lib/artifacts.ts` — `ArtifactType` widened for `path_options_session`
  (same as Slice 1 did for `path_direction_session`); separately,
  `PathOptionsSessionStatus` widened to include `'failed'` — a real 4th
  value the generation routes' catch blocks always wrote, but never
  previously needed a typed `=== 'failed'` comparison against (surfaced by
  a real `tsc` error while wiring the GET resume fix, not by inspection).

### Decisions

- Must-avoid check: case-insensitive phrase-presence against each
  `must_avoid` string and close lexical variants, negation-aware. Why: a
  pure phrase-presence check with no negation logic rejects every option
  that correctly explains its own compliance, confirmed via a real 12/12
  rejection run.
- Material-difference check: phrase-overlap heuristic (same family as
  `enforceConstellationSynthesisNonOverlap`), threshold 14 words. Why:
  calibrated against a real captured false positive, not picked blind — see
  Changed above.
- Generation control flow: over-generate N+2, take first N passing both
  checks, one bounded retry sized `shortfall + 2` (not `shortfall` alone),
  hard-fail (typed `OptionsGenerationShortfallError`) if still short. Why: a
  shortfall-sized retry with zero cushion would have a materially worse
  chance of closing the gap than the first attempt did.
- UI per-card pattern: recovered pre-#129 markup (`.constellation-card`,
  per-card "Select This Path →"), not the more recent Stage D pattern. Why:
  Stage D's version is the exact "one shared button below a stack of cards"
  flaw brief §4 was written to fix — confirmed via git history before
  writing any component code, not assumed from the brief's prose alone.
