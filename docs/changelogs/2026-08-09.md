## 2026-08-09 — #113: move reframe generation from /identity to /path

Per `docs/briefs/113-move-reframe-generation-brief.md`. Reverses #98's
original architecture: `identity_reframe` generation used to fire eagerly
on `/identity` the moment `identity_report` completed, before the user had
shown any interest in paying. Moved that trigger to `/path`'s unpaid state
(which already had the correct, unconditional trigger logic from #98 —
confirmed before touching anything) and folded a short teaser directly
into `identity_report`'s own Layer 2 generation, so `/identity` no longer
depends on a second artifact/LLM call at all.

### Changed
- **`lib/artifact-schemas.ts`** — new optional `reframe_teaser` field
  (`shift` + `line`) on the identity report content. Top-level, never
  nested inside anything recomputed post-generation — same no-backfill
  precedent as `domain_profile_summary` (#103).
- **`lib/prompts/identity-report.ts`** — new REFRAME TEASER section
  requesting `reframe_teaser`. Placeholder instruction only, flagged
  inline as provisional — #99 owns the real copy/wording pass.
- **`app/identity/page.tsx`** — removed `reframeArtifactId`/
  `reframeGenPhase` state, the generation-trigger effect, and all polling
  render branches (idle/spinner/come-back-later/failed/ready), including
  the checkout CTA that lived alongside them. The teaser is recognition,
  not a pitch — the fuller identity_reframe pitch with its CTA now lives
  entirely on `/path`. Replaced with a direct render of
  `reframe_teaser.shift`/`.line` off the already-loaded report object —
  no second fetch, no polling.
- **`app/path/page.tsx`** — no logic changes. Confirmed its existing #98
  `loadOrStartReframe`/`reframeGenPhase` logic in the `unpaid` branch was
  already unconditional and already correct for this ticket. Updated a
  stale comment that compared it to `/identity`'s now-removed

- **`lib/prompts/identity-reframe.ts`** — confirmed, no change needed. It

## 2026-08-09 — AGENTS.md: scope docs/briefs cleanup into session end

`docs/briefs/` should stay clean at all times, but nothing here has
access to the ticket-tracking CSV, so ticket status can't be inferred
from the folder alone — a blanket "delete shipped briefs" scan risked
deleting briefs for tickets that only looked shipped from file contents.

### Changed

  narrowly-scoped brief-cleanup step: delete only the brief(s) actually

  implementation was both committed and live-verified in the same
  session. No scanning `docs/briefs/` for any other file. Requires
  stating which ticket and confirming both conditions explicitly, as
  its own message, before presenting the deletion as a normal
  approval-gated command — kept in its own commit, separate from
  feature/changelog commits.
- **`docs/briefs/113-move-reframe-generation-brief.md`** deleted,
  applying the new rule to this session's own #113 work (implemented in
  `60424e8`, live-verified earlier this session — see the entry above).

### Decisions

  "any brief whose ticket looks done" — the latter would require
  inferring ticket status from file content/git history, which is
  exactly the kind of judgment call the ticket CSV (inaccessible here)
  is meant to own, not this repo. Decided 2026-08-09, per Miroslav's
  explicit instruction.

## 2026-08-09 — #99: /identity teaser real content, schema, and composition

Per `docs/briefs/99-identity-teaser-content-brief.md`. Replaces
`reframe_teaser`'s #113 placeholder (`shift`/`line`) with the locked
7-component composition: two static eyebrows, a generated recap, a
generated pull-quote reframe, 3 generated evidence bullets, a static
bridge line, and a CTA to `/path`. Content/rendering only — #113's
generation mechanics (folded into `identity_report`'s own Layer 2 call)
were unchanged.

### Changed
- **`lib/artifact-schemas.ts`** — `ReframeTeaser` is now `{ recap, reframe,
  why_bullets: string[] }`, replacing `{ shift, line }`.
- **`lib/prompts/identity-report.ts`** — real `reframe_teaser` instructions
  replacing #113's placeholder. Went through several live-verified rounds
  this session (see Decisions) before landing on: explicit word-count
  floors with a self-count-before-finalizing instruction (45/15/15 words),
  no full example sentence for `reframe` (caused verbatim copying — see
  below), a banned-word list for `reframe` ("gap," "room," "chance,"
  "opportunity," etc.) to stop it resolving into an upside instead of an
  open tension, a short→extended worked example for `why_bullets` to push
  length up, and a one-line British-English-spelling instruction scoped to
  this field.
- **`lib/generate-identity-report.ts`** — new `logReframeTeaserWordCountGaps`,
  called once per generation right after the other post-processing
  enforcement calls. Log-only: counts words in `recap`/`reframe`/each
  `why_bullets` entry against their floors and `console.warn`s any gaps.
  Does not rewrite content, does not block generation, does not fire a
  second LLM call — confirmed via live runs that `reframe_teaser` is still
  produced by exactly one Layer 2 call.
- **`app/identity/page.tsx`** — full 7-component render replacing the old
  2-field placeholder. Two eyebrows reuse the existing `.eyebrow` class
  (no duplicate style). Render guard changed from a bare `reframe_teaser &&`
  truthy check to `reframe_teaser?.recap && reframe_teaser.reframe &&
  Array.isArray(reframe_teaser.why_bullets) &&` — the truthy-only check
  crashed on the old `shift`/`line` shape (`why_bullets.map()` on
  `undefined`), caught via the legacy-regression live check (see
  Verification).
- **`app/globals.css`** — two new scoped classes appended at file end
  (per this project's cascade-order convention): `.reframe-pullquote`
  (3px solid `--color-accent` left border, italic Georgia serif, 20px)
  and `.reframe-bullets` (dash-prefixed list via `::before`, not shared
  with `ChipRow`/chip styling).

### Verification
- `npx tsc --noEmit` clean throughout.
- **Live**, via `scripts/run-verification.mts` (temporary ad hoc scripts,
  deleted after use, not committed) against a real dev server:
  1. Real end-to-end generation, multiple rounds as the prompt was tuned —
     seeded 13 realistic discovery answers for a synthetic user, ran the
     actual Detection + Layer 2 LLM pipeline (`generateIdentityReport`)
     end to end. Final run: `recap` 49 words, `reframe` 18 words
     declarative with no banned words and an open/unresolved ending,
     all 3 `why_bullets` cite specific facts from the seeded answers
     (a six-week workflow redesign, mentoring, dropped process reviews),
     no signature names leaked anywhere, British spelling confirmed
     (`revitalised`, `stabilise`, `energises`) — one miss (`optimization`)
     left as-is, tracked under #97 rather than fixed as a one-off.
  2. Legacy/missing-field regression — seeded the old `shift`/`line` shape
     and a report with `reframe_teaser` entirely absent; both rendered
     nothing in that section with zero page errors, confirming the render
     guard fix above.
  3. CTA click-through — confirmed via Playwright locator on every run:
     text "Explore Your Path Options", `href="/path"`. Grep confirmed no
     stale `shift`/`line` references anywhere in source.
  4. Visual check — screenshot of the rendered section confirmed against
     the locked mockup: eyebrow styling, pull-quote border/italic/size,
     dash bullets, CTA all match.
  - All ad hoc scripts, screenshots, and the temporary dev server used for
    this pass were deleted/stopped after — not committed.

### Decisions
- **Word-count floors enforced by log warning, not regeneration.** Early
  in this session's tuning, prompt-only instructions left `reframe`/
  `why_bullets` landing a few words under their floors on some runs
  despite explicit "count your words" self-check language. Considered an
  automatic one-shot regeneration call for under-floor fields; Miroslav
  called it back to log-only — `logReframeTeaserWordCountGaps` flags gaps
  for review, never fires a second LLM call or blocks generation. Decided
  2026-08-09.
- **No full example sentence in `reframe`'s prompt instructions.** Two
  consecutive live rounds showed the model copying a "right" example
  sentence verbatim, and then — after re-labeling it "wrong" — copying
  that one verbatim too. Concluded the model pattern-matches on any
  literal sentence in the prompt regardless of its right/wrong label, at
  this call's `temperature: 0`. Fixed by describing the two failure modes
  (stopping at exhaustion without naming what's missing; resolving into
  an upside) in the abstract only, plus an explicit banned-word list for
  the "opportunity/upside" failure mode specifically, since abstract
  description alone didn't reliably prevent it. Decided 2026-08-09.

- The `optimization`/`optimisation` British-spelling miss observed in one
