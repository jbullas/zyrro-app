## 2026-08-09 — #113: move reframe generation from /identity to /path

Per `docs/briefs/113-move-reframe-generation-brief.md`. Reverses #98's
original architecture: `identity_reframe` generation used to fire eagerly
on `/identity` the moment `identity_report` completed, before the user had
shown any interest in paying. Moved that trigger to `/path`'s unpaid state
(which already had the correct, unconditional trigger logic from #98 —
confirmed before touching anything) and folded a short teaser directly
into `identity_report`'s own Layer 2 generation, so `/identity` no longer
depends on a second artifact/LLM call at all.

### Changed
- **`lib/artifact-schemas.ts`** — new optional `reframe_teaser` field
  (`shift` + `line`) on the identity report content. Top-level, never
  nested inside anything recomputed post-generation — same no-backfill
  precedent as `domain_profile_summary` (#103).
- **`lib/prompts/identity-report.ts`** — new REFRAME TEASER section
  requesting `reframe_teaser`. Placeholder instruction only, flagged
  inline as provisional — #99 owns the real copy/wording pass.
- **`app/identity/page.tsx`** — removed `reframeArtifactId`/
  `reframeGenPhase` state, the generation-trigger effect, and all polling
  render branches (idle/spinner/come-back-later/failed/ready), including
  the checkout CTA that lived alongside them. The teaser is recognition,
  not a pitch — the fuller identity_reframe pitch with its CTA now lives
  entirely on `/path`. Replaced with a direct render of
  `reframe_teaser.shift`/`.line` off the already-loaded report object —
  no second fetch, no polling.
- **`app/path/page.tsx`** — no logic changes. Confirmed its existing #98
  `loadOrStartReframe`/`reframeGenPhase` logic in the `unpaid` branch was
  already unconditional and already correct for this ticket. Updated a
  stale comment that compared it to `/identity`'s now-removed
  eager-generation behavior.
- **`lib/prompts/identity-reframe.ts`** — confirmed, no change needed. It
  already receives the full `identity_report` JSON as input context, so
  `reframe_teaser` reaches it automatically. No anchoring instruction
  added between teaser and pitch, per scope (that's #99).

## 2026-08-09 — AGENTS.md: scope docs/briefs cleanup into session end

`docs/briefs/` should stay clean at all times, but nothing here has
access to the ticket-tracking CSV, so ticket status can't be inferred
from the folder alone — a blanket "delete shipped briefs" scan risked
deleting briefs for tickets that only looked shipped from file contents.

### Changed
- **`AGENTS.md`** — `session end` protocol now includes an explicit,
  narrowly-scoped brief-cleanup step: delete only the brief(s) actually
  read and executed *this session*, and only once that ticket's
  implementation was both committed and live-verified in the same
  session. No scanning `docs/briefs/` for any other file. Requires
  stating which ticket and confirming both conditions explicitly, as
  its own message, before presenting the deletion as a normal
  approval-gated command — kept in its own commit, separate from
  feature/changelog commits.
- **`docs/briefs/113-move-reframe-generation-brief.md`** deleted,
  applying the new rule to this session's own #113 work (implemented in
  `60424e8`, live-verified earlier this session — see the entry above).

### Decisions
- Scoped the cleanup trigger to "brief used this session" rather than
  "any brief whose ticket looks done" — the latter would require
  inferring ticket status from file content/git history, which is
  exactly the kind of judgment call the ticket CSV (inaccessible here)
  is meant to own, not this repo. Decided 2026-08-09, per Miroslav's
  explicit instruction.
