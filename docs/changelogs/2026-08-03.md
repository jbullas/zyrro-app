## 2026-08-03 — #98 identity_reframe artifact: restructure /identity + /path pitch

Per `docs/briefs/98-identity-reframe-artifact-brief.md`. Moves the
recap/meaning/reframe/why pitch content out of `path_options` (previously
generated in one call, only after payment) into its own dedicated free
artifact, `identity_reframe`, generated eagerly the moment the identity
report finishes rendering. Structural only — no wording/content-quality
changes (that's #99) and no touch to `path_options`' option-generation
logic, stretch-distribution rules, or option quality (that's #25).

### Changed
- **Migration** `20260803000000_identity_reframe_artifact.sql` — extended
  `artifacts_type_check` to include `identity_reframe`; added
  `artifacts_one_identity_reframe_generating_per_user`, a partial unique
  index scoped to `status = 'generating'`, same shape as `identity_report`'s
  own guard (#71 precedent). Applied to the live Supabase project and
  confirmed via `pg_get_constraintdef`/`pg_indexes` (not just committed —
  actually verified live).
- **`lib/artifact-schemas.ts`** — added `IdentityReframeArtifactContent`
  (`recap`/`meaning`/`reframe`/`why`); `PathOptionsArtifactContent` narrowed
  to `{ options }` only.
- **`lib/artifacts.ts`** — `ArtifactType` extended with `'identity_reframe'`.
- **`lib/prompts/identity-reframe.ts`** (new) — recap/meaning/reframe/why
  sections ported verbatim (no wording changes) out of `PATH_OPTIONS_PROMPT`;
  options section and its validation rules removed entirely.
- **`lib/prompts/path-options.ts`** — narrowed to options-only; removed the
  four ported sections and their instructions; `INPUTS YOU RECEIVE` updated
  to describe the new `{identity_report, identity_reframe}` input shape so
  options don't contradict the pitch the user already read.
- **`app/api/generate-identity-reframe/route.ts`** (new, `maxDuration=240`)

  row same as `completeDiscovery`'s guard shape), 404s if no ready

- **`lib/generation-status.ts`** — comment updated from "five generation

- **`app/identity/page.tsx`** — fires `generate-identity-reframe` eagerly in
  the background once the report renders (independent of any click);
  Section 11 (`LimitsBlock`) replaced with a click-gated "What does this
  mean?" CTA that reveals the four fields plus a payment CTA (reusing
  `/api/checkout`, same as `/path`'s flow).
- **`app/path/page.tsx`** — new explicit "no `identity_report` yet" state,
  checked before the entitlement check (previously this silently
  fell through to the generic static offer page); `'unpaid'` state now
  renders the real `identity_reframe` pitch (unconditional trigger, no
  click gate — the pitch *is* the page) instead of static `OFFER_FEATURES`

- **`scripts/verification/session.mts`** — `ArtifactType`/

### Decisions
- Generation trigger is a dedicated, client-triggered route rather than
  chained inside `generateIdentityReport()`'s own background job — avoids
  nesting a second `after()` inside a function already running inside one,
  and keeps `generate-identity-report.ts` ignorant of `identity_reframe`
  entirely. Full rationale in the brief.
- Declined to add server-side event logging for the "What does this mean?"
  CTA click (brief mentioned it as a nice-to-have, not a deliverable) —
  flagged mid-session as scope creep and dropped rather than building it.

### Verification

- **Live end-to-end**, real OpenAI generation calls, against a dedicated
  dev server (port 3100) started with `NEXT_PUBLIC_OPEN_ACCESS=false` so
  the real entitlement-gated branches of `/path` were actually reachable
  (the default `.env.local` value bypasses that check entirely). Covered:
  `/path` with no `identity_report` → no-report state; `/identity`'s eager

  reveal working post-click; `/path`'s own unconditional trigger firing a
  second real generation; `/path` paid state rendering exactly 4 real path
  options with recap/meaning/reframe/why absent; `generate-path-options`
  409ing with no ready `identity_reframe`.

  buttons) that had nothing to do with app code — confirmed via isolated
  diagnostics (direct DB reads, DOM dumps) before concluding the app logic
  was correct all along, then fixed the selector and re-ran clean.
